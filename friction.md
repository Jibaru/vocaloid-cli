# friction.md

Running log of surprises, rejected options and wrong assumptions. This gets folded into the
case file at the end (cli-build Phase 6).

## Phase 0: classification

**Mixed.** The canonical song model is defined by us. The VOCALOID formats, the OpenUtau
`.ustx` format and the engine behaviour are discovered.

## Phase 1: spike (2026-10-12)

### Starting point and build

- No VOCALOID is installed and there is no official CLI or headless render for V5/V6. The
  scope moved from "project file generator" to "full audio pipeline with an open-source
  engine". The VOCALOID formats became export targets.
- Upstream OpenUtau rejected headless rendering (issue #1615). The community fork
  `boxboy523/OpenUtau-Headless` adds `OpenUtau.Cli`.
- The fork builds on .NET 8 (not 10, as research suggested). It was installed locally with
  `dotnet-install.sh` into `~/.dotnet`, with no sudo.
- `dotnet publish -r osx-arm64 --self-contained` produces 159 MB. Trimming is still to try.

### Hanami voicebank

- Hoshino Hanami ~AI❤dol~ v1.0 (DiffSinger, 550 MB zip) is distributed only through
  MediaFire. A direct link can be scraped from the page, but that is fragile. **Consider
  mirroring** in our own GitHub release if the license allows redistribution, or keep a
  resolver with a checksum.

### Render results

- **Japanese (kana lyrics, DiffSingerJapanesePhonemizer):** renders in about 3.3 s wall time
  for a 4.6 s phrase.
- **English failed at first:**
  - **Bug 1:** the headless renderer waits 60 s and then reports a generic
    `TimeoutException`, hiding the real phonemizer error. Opt-in Serilog stderr logging was
    added (`OPENUTAU_CLI_LOG=Error`). **TODO in the fork:** fail fast with the phonemizer
    error instead of timing out. That error is the actionable one for agents.
  - **Bug 2 (upstream):** `DiffSingerG2pPhonemizer` prefixes every base G2P phoneme with
    `en/`, even for single-language voicebanks whose symbols are bare (`aa`, not `en/aa`).
    **Fix:** only prefix when the voicebank defines the prefixed symbol. Patch in
    `engine/openutau-headless.patch`. Worth upstreaming.
- **English lyric convention:** a multi-syllable word goes on its first note, followed by `+`
  continuation notes (`twinkle`, `+`). Splitting syllables (`twin`, `kle`) is not the input
  OpenUtau's English G2P expects. This shapes `lyrics fit` for English.
- Hanami's ToU forbids reuploading the original voicebank ("refer to the original download link instead") and requires crediting Lotte V. So no mirror: `voice install` resolves the original MediaFire link and verifies a sha256. Custom dictionaries may be redistributed.

## Phase 2–3: core + instrumental (2026-10-12)

### Fork changes

- **Phonemizer errors fail fast:** the fork now returns a structured `PhonemizationException`,
  exit 6, with `{tick, lyric, error}`, instead of a 60 s timeout. The CLI maps each tick back to
  `tracks[i].notes[j].lyric`.
- **Partial failures fail:** a partial phonemization failure used to *succeed* with a silent note.
  Any phoneme error now fails the render. An agent should never hear silence and think the job
  worked.

### Engine format and stems

- **.ustx 0.9 renders**, generated by the CLI and loaded by the engine; default expressions are
  registered on load.
- **Per-track stems:** every vocal track renders as its own .ustx. Part positions are absolute,
  so stems stay aligned with tick 0, and per-track caching is a content hash of the .ustx plus the
  engine version.
- **Mix:** ffmpeg alone (amix + loudnorm) is enough; no Python or pedalboard is needed so far.
  GeneralUser GS (32 MB, commercial use allowed) is pinned to a commit with a sha256.

### Human output, read in a real pty

- **The pty script itself:** `script` fails in the sandbox ("Operation not supported on socket"),
  so a Python pty runner was used. Naming that runner `tty.py` shadowed the stdlib `tty` module;
  it was renamed.
- **Defects the tests did not catch:**
  - Drum tracks showed a meaningless pitch range (C2-F#2), now hidden.
  - `note list` showed an all-dash lyric column on instrument tracks (vertical repetition), now
    replaced by velocity.
  - `note list` showed drum hits as pitch names, now shown as drum names.
- **Path display:** `init` nextSteps printed a 5-level `../` relative path; it now uses whichever
  of relative or absolute is shorter.
- **`bun` as a runner:** reports `process.versions.node` as 24.3.0, so `doctor`'s node check
  under bun is not meaningful. The built `dist/cli.js` runs under real node.

### Distribution and workflow

- **zsh:** `$V` holding "bun src/cli.ts" does not word-split, so the CLI was linked early
  (`bun link`) and invoked by name. That matches cli-build Phase 6 anyway.
- `tonal` 6.5.0 declares `"types": "dist/index.d.ts"` but ships only `.d.mts`/`.d.cts`; tsc cannot resolve it. Worked around with a `paths` entry in tsconfig.json (runtime is unaffected).

## Phase 4: composition helpers (2026-10-12)

### Arrangement storage

- **Materialized notes broke the agent's context.** The first `arrange` wrote 7,600 generated
  notes into song.yaml (450 KB), which no agent can read. It also went stale whenever the chords
  changed.
- **Redesign:** tracks carry `generate: {part}`, and notes are generated at compile time from
  `chords` and `sections`. song.yaml dropped to 5 KB. `--freeze` materializes the notes for hand
  edits. **Decision:** derived data stays out of the source of truth.

### Lyrics and the phonemizer

- **`-` is not a continuation on Hanami.** Hanami's dictionary maps `-` to SP (silence). My
  first SKILL.md claimed `-` extends the vowel. That was wrong, and it was caught by reading
  dsdict-ja.yaml.
- **`+` is the continuation, with a condition.** OpenUtau treats `+` as a slur only when the note
  starts exactly at the previous note's end (UPart.cs:111). That rule is now a compile-time error
  with a path.
- **Katakana selects different vowel phonemes on Hanami.** For example カ → [kx, A] while
  か → [kx, a]. Hiragana is recommended.
- **Kanji is never guessed.** `lyrics split/fit` refuses it with LYRICS_UNPARSED and asks for
  the reading. A first version silently dropped kanji mixed with kana ("君の声" → "の").
- **English syllable heuristic:** `[aeiouy]{1,2}` split "beautiful" into 4. It now uses
  `[aeiouy]+`. Hyphens override the heuristic.

### Mix and tooling

- **Vocal effects:** the vocal sounded dry on top of the mix, so per-track fx chains were added in
  ffmpeg (highpass, acompressor, aecho). Still no Python.
- **`tonal` types:** 6.5.0 points `types` to a file it does not ship (see the tsconfig `paths`
  workaround).
- `engine/build.sh` failed on a fresh clone with MSB3577 ("Two output file names resolved to the same output path: OpenUtau.Core.Resources.resources"). First guess (a global `-p:TreatWarningsAsErrors=false`) was wrong: removing it changed nothing. Real cause: macOS `mktemp -d` returns `/var/...`, a symlink to `/private/var/...`, and MSBuild resolves the three `Resources.resx` DependentUpon paths inconsistently under it. Fixed with `pwd -P` and building from inside the repo. A manual build in a non-symlinked dir had masked it.
- `--progress json` first emitted one NDJSON line per network chunk: 19,457 lines for the 550 MB voice download. Throttled to one event per whole percent per task (plus the final one).
- `npm publish` goes through staged publishing: for ~2 min `npm view` returned `0.0.0-stage` and `npx pkg@0.1.0` failed with ETARGET before 0.1.0 appeared. A `0.0.0-stage` version stays listed in the registry. Verify with `npx` only after `dist-tags.latest` updates.
